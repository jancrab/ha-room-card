# HA Room Card working guide

- Build and maintain the actual installable HA Room Card in src/, bundled to dist/ha-room-card.js. The user expects the room UI and native visual editor in the released file, not a separate starter. Keep one card per room, with actual entity mappings and real HA services; do not hard-code user entities.
- Preserve the compact layout, per-room section/item visibility settings and automation enable/disable controls. Real-card configuration belongs in dashboard YAML via config-changed events, not browser local storage. Excluded entities must not be controlled by group actions. The canonical demo/ha.html loads the real bundle with explicitly mocked HA transport; demo/index.html is the original design prototype.
- Area suggestions use entity/device registries in the editor, fill only empty mappings and preserve manual overrides. Search may cross room boundaries; runtime mappings stay explicit. Occupancy uses binary state and last_changed; optional post-off hold must say Recent activity. Heating tint follows HVAC action, with off/unavailable taking precedence.
- Keep humidity and window/door state durations small on the cards; expose supported dimmers and native HA entity details/history in room details. Never show illustrative history in the real card. Scenes are momentary actions. Unavailable controls and failed commands must not masquerade as off/successful state. HVAC activity is independent of the target/current temperature comparison.
- Read docs/working-guide.md before modifying editor, device actions or releases. Keep verified new lessons there.
- Keep the UI and documentation in English; respond in the user's language. Use Home Assistant themes, accessible names, keyboard focus, 44px targets and reduced-motion support.
- Implement controls from actual supported features and exact service parameters. Respect thermostat bounds, device temperature steps, range modes and HA units; use supported_color_modes for dimmers. Never optimistically mutate hass.states. Report rejected, timed-out and unconfirmed commands separately from confirmed state changes.
- Preserve native editor bootstrap, context subscription cleanup and reused-hass rendering. Keep configuration minimal and preserve unknown fields on editor updates.
- Run npm run check after card changes. Test meaningful state/service failures. Distinguish mocked previews from real Home Assistant or device verification.
- Commit package-lock.json and the built dist/ha-room-card.js with source changes. Runtime code must not depend on a CDN.
- Before releasing, synchronize package and lock versions, update CHANGELOG.md, rebuild, verify CI, and use a matching v-version tag. Confirm the actual GitHub release asset and HACS validation.
- Check git status and preserve unrelated work. Use the requested repository-local Git author/committer identity; do not change global identity or rewrite old commits implicitly.
- Repository creation, pushing, publishing, visibility changes and releases require authorization from the task. A credential, this guide or past authorization for another repo does not authorize those actions.
